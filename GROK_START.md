# Grok — с чего начать (шпаргалка по папкам)

> Это короткая версия. Полный протокол — в `HANDOFF.md`, полный бриф по
> тону/лору/механике — в `BRIEF_FOR_AI.md`. Этот файл — просто «что куда»,
> чтобы не листать оба с самого начала.

---

## 1. Кто есть кто

- **Флинт** — автор проекта. Единственный, кто вносит правки в канон и
  единственный, кто пушит в GitHub.
- **Claude** — второй ИИ-соисполнитель. Работает независимо от тебя,
  результата твоего не видит, пока Флинт не решит показать.
- **Ты (Grok)** — исполнитель, как и Claude. Можешь спорить с заданием,
  предлагать своё, отказываться от плохой идеи — но не можешь сам решить,
  что теперь канон.

У тебя и у Claude нет прямого доступа к репозиторию — ни ты, ни Claude не
пушите сами. Вы оба отдаёте текст/файл, Флинт руками кладёт его в нужную
папку и коммитит. Это не ограничение лично для тебя — Claude работает по
той же схеме.

---

## 2. Что читать по порядку

1. **`STATE.md`** — целиком, всегда первым. Что уже решено, что открыто,
   какая версия лор-библии актуальна.
2. **`BRIEF_FOR_AI.md`** — целиком. Тон истории, стиль письма, механика
   резонансного индикатора, типичные грабли (реальные люди, тихая выдумка
   канона, реткон без объявления).
3. **Карточка задачи** из `tasks/` — там написано, что конкретно делать и
   какие разделы `lore/lore_bible.md` читать под эту задачу.
4. Только после этого — сами файлы канона, на которые ссылается карточка.
   Не всю лор-библию целиком, а именно указанные разделы.

Если задачи про механику — обязательно открой `prototype/prototype_scene.html`
в браузере и поиграй, прежде чем что-то предлагать. Это файл, не ссылка,
работает офлайн.

## 3. Карта папок

| Папка | Что там | Можно ли писать тебе |
|---|---|---|
| `STATE.md`, `lore/lore_bible.md`, `design/*`, `prototype/*` | **Канон.** Согласованный, актуальный материал | **Нет.** Даже если видишь опечатку — не трогаешь, пишешь об этом в своём результате |
| `lore/archive/` | Старые версии лор-библии, для истории | Нет, только для справки |
| `tasks/` | Карточки задач от Флинта | Нет, это входящее |
| `inbox/from-claude/` | Результаты Claude | Нет, это не твоя папка |
| **`inbox/from-grok/`** | **Твоя рабочая папка** | **Да — сюда кладёшь всё, что делаешь** |
| `art/` | Референсы и концепт-арт | Да, если задача про визуал |

Короче: **читаешь везде, пишешь только в `inbox/from-grok/`.**

## 4. Как физически сдать результат

Ты не работаешь напрямую с git — просто отдаёшь Флинту готовый текст
(или файл, если у тебя есть такая возможность). Дальше он сам сохраняет
его по адресу:

```
inbox/from-grok/T-XXX_название-задачи.md
```

Правила именования:
- Номер задачи из карточки — обязателен в начале имени.
- Если есть отдельные замечания не по самой задаче, а вокруг —
  отдельным файлом `T-XXX_..._NOTES.md`, не внутри основного результата.
- Никаких `финал.md`, `версия2.md` — только один файл на задачу, лучшая
  версия сразу.

**В конце результата — обязательный блок**, без него результат не
принимается на сравнение:

```markdown
## ЗАЯВКА В КАНОН

**Файлы, которые предлагаю изменить:**
- lore/lore_bible.md — раздел 4.1, добавить абзац про X

**Что меняется по сути:**
- (одна-две строки на каждое изменение)

**С чем это конфликтует:**
- (честно, если правка спорит с уже написанным)

**Что осталось нерешённым:**
- (вопросы, которые нужно закрыть Флинту)
```

## 5. Три вещи, за которые сразу минус

- **Не выдумывать канон молча.** Не знаешь — пиши «в каноне не
  определено, предлагаю вариант», а не выдавай догадку за факт.
- **Не трогать чужое.** Не видел работу Claude — и не должен видеть до
  сдачи (сейчас режим, где вы оба решаете одну и ту же задачу
  независимо). Не подстраивайся под то, что «наверное, уже решено» —
  если не написано в файлах канона, значит, не решено.
- **Реальные люди и организации — только фон.** Все персонажи и
  структуры в проекте вымышлены; реальным узнаваемым людям и
  существующим организациям вымышленные тайные дела не приписываем.
  Если задача подталкивает в эту сторону — сказать прямо и предложить
  вымышленную замену.
